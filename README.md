#  Linux Terminal 단톡방 (System Programming Team 5)

리눅스 서버 내에서 다수의 사용자가 터미널을 통해 실시간으로 쪽지를 주고받을 수 있는 **멀티스레드 기반 TUI 채팅 프로그램**입니다.

## 1.  프로그램 소개 (Core Concepts)

* **도메인 소켓 (Unix Domain Socket)**
  * 외부 네트워크망(TCP/IP)을 타지 않고, 하나의 리눅스 서버 안에서 작동하는 인트라넷 형태의 빠르고 안전한 통신 방식을 사용합니다.
* **이벤트 기반 다중 접속 처리 (`epoll`)**
  * 여러 명이 접속했을 때 프로세스를 무한정 복제(`fork`)하거나 계속 순환하며 검사하지 않습니다.
  *  **진동벨 시스템:** 식당에서 매니저가 테이블을 계속 돌아다니지 않고 진동벨이 울린 곳만 찾아가듯, `epoll`을 사용해 이벤트(메시지)가 발생한 소켓의 데이터만 즉각적으로 처리하여 서버 부하를 최소화합니다.
* **멀티스레드와 TUI (`pthread` & `ncursesw`)**
  * 내가 타자를 치는 동안에도 상대방의 채팅을 실시간으로 수신하기 위해 **송신과 수신 스레드를 분리**하여 작동합니다.
  * 한글 텍스트 깨짐 현상을 방지하기 위해 와이드 문자 라이브러리(`ncursesw`)를 채택했습니다.

---

## 2.  작동 방식 및 구조 (Architecture)

프로그램은 크게 3개의 모듈로 나뉘어 독립적으로 작동하며, 최종적으로 결합됩니다.

* **`server.c` (서버 코어)**
  * 누군가 메시지를 서버로 보내면, 현재 접속해 있는 다른 모든 사람들에게 해당 메시지를 복사해서 전달(Broadcast)합니다.
* **`client.c` (클라이언트 및 UI)**
  * 화면을 구성하는 TUI 영역입니다. 서버와의 송수신을 담당하는 멀티스레드 로직이 포함됩니다.
* **`old_chat.c` (파일 입출력 및 기록)**
  * 오간 대화를 로그 파일에 저장하고, 사용자가 요청 시 이전 대화 기록을 불러오는 서기 역할을 합니다.

## 3.  파트별 역할 분담 (R&R)

| 역할 | 담당자 | 핵심 사용 기술 (System Calls) | 주요 구현 내용 |
| :---: | :---: | :--- | :--- |
| **서버 코어** | **김종민** | `epoll`, `socket` (AF_UNIX) | - 다수 인원 접속 시 세션 관리 (튕김 방지)<br>- 수신된 메시지를 전체 접속자에게 브로드캐스트 |
| **TUI 화면** | **서정빈** | `ncursesw`, `pthread`, `mutex` | - 상/하단 터미널 창 분할 및 방향키 스크롤 구현<br>- 한글 인코딩 유지<br>- **Mutex 락:** 타자 입력 중 메시지 수신 시 화면 깨짐 방지 (UI 잠금/해제) |
| **파일 기록** | **권은서** | `open`, `read`, `write` | - 저수준 파일 I/O를 활용한 채팅 기록 저장<br>- 이전 채팅 내역 불러오기 |
| **빌드** | **김유빈** | `Makefile`, 아키텍처 설계 | - 프로젝트 통합 테스트 및 시나리오별 시연 영상 녹화<br>- 프로그램 구조도(아키텍처) 및 발표 PPT 제작 |

---

## 4.  협업 및 코딩 규칙 (Ground Rules)

프로젝트 모듈 결합 시 충돌을 방지하기 위해 아래 규칙을 엄격히 따릅니다.

1. **공통 헤더 파일(`chat.h`) 배포 및 고정**
   * 각자의 C 파일 상단에 해당 헤더를 `#include` 하여 사용합니다.
   * 변수명, 패킷(메시지를 담는 편지 봉투)의 구조체 형태와 크기는 헤더에 지정된 **규격화된 상태**로만 사용합니다.
2. **헤더 파일 임의 수정 금지**
   * 프로젝트 진행 중 헤더 파일에 새로운 구조체나 상수 추가/수정이 필요할 경우, **반드시 단톡방에 사전 공유 후 다 함께 수정**합니다.
